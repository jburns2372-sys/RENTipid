# RENTipid Future Module Knowledge Contract

Every future RENTipid module must register approved durable knowledge in the frozen Knowledge Engine registry before closure. Live transactional data remains behind authorized domain services and AI tools and must not be copied into knowledge records.

Required promotion gates, in order:

1. CODE COMPLETE
2. LOCAL FUNCTIONAL
3. LOCAL DATABASE MIGRATED
4. LOCAL REQUIRED DATA SEEDED/SYNCED
5. LOCAL KNOWLEDGE REGISTERED
6. LOCAL KNOWLEDGE SYNCED
7. LOCAL ACCEPTANCE PASS
8. PREVIEW MIGRATED
9. PREVIEW REQUIRED DATA SEEDED/SYNCED
10. PREVIEW KNOWLEDGE SYNCED
11. PREVIEW ACCEPTANCE PASS
12. OWNER ACCEPTANCE PASS
13. PRODUCTION-READY
14. CLOSED / FROZEN

A registration must supply stable source keys, module ownership, authority, approval evidence, visibility, roles, version, adapter, and disposition. It must pass secret/PII validation and reach 100% module knowledge coverage. Previously frozen module source does not need modification when its approved knowledge can be registered externally.
